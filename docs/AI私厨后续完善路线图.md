# AI 私厨后续完善路线图

## P0：上线前必须完成

1. Web 正式认证：增加手机号验证码登录或微信扫码登录，停用生产环境体验登录。
2. 服务间安全：生成高强度 `CLOUD_MEAL_AI_SERVICE_TOKEN`，限制 8081 仅内网可访问。
3. HTTPS 与域名：配置 Nginx、证书、小程序业务域名和 AI/支付公网回调。
4. 真实支付验收：沙箱/小额支付、回调验签、重复回调、主动查单与退款全链路测试。
5. 数据迁移：将 AI H2 会话迁移到 MySQL/PostgreSQL，使用 Flyway 管理表结构；现有 `user_id IS NULL` 的历史本地会话默认不归属任何云膳用户，需确认后再迁移，禁止自动分配。

## P1：稳定性与性能

1. 将 AI 分析改为异步任务：请求返回 taskId，SSE/WebSocket 推送“识别、检索、生成、匹配”进度。
2. 按用户和 IP 增加限流、并发上限、请求取消和 30–60 秒结果短缓存。
3. 增加 Resilience4j 超时、熔断和仅对安全错误的一次退避重试。
4. 增加 Micrometer 指标：AI P50/P95、模型错误率、Token 成本、菜单匹配点击率和加购转化率。
5. 菜单规模扩大后，使用关键词倒排/向量召回缩小候选集，再执行确定性库存过滤。

## P2：产品体验

1. AI 会话历史页、重命名、收藏菜谱、再次下单和多轮追问。
2. 小程序悬浮图标支持安全区域避让和可拖动停靠。
3. Web 补充地址管理、优惠券领取/选择、订单详情、删除订单和支付结果轮询。
4. 基于过敏原、疾病饮食和忌口建立结构化规则，在模型输出后再做服务端校验。
5. 图片上传增加客户端压缩、EXIF 清理、对象存储临时 URL 与内容安全审核。

## P3：求职简历增强点

- 使用 Testcontainers 完成 MySQL/Redis/RabbitMQ 集成测试；
- 使用 Pact 或 OpenAPI Diff 做云膳与 AI 服务契约测试；
- GitHub Actions 增加前后端构建、镜像扫描、接口回归和预发布部署；
- 输出压测报告：菜单查询、加购、下单和 AI 并发的吞吐、P95 与资源占用；
- 增加可观测性链路：traceId 从小程序/Web 贯穿云膳、AI、RAG 与模型请求。

## 建议迭代顺序

先完成 P0 的认证、安全和生产环境，再做异步 AI 与监控，最后扩展推荐算法和个性化。任何 AI 功能升级都必须保持：交易数据只由云膳服务写入、下单前重新校验价格/库存、接口继续使用统一 `ApiResponse`。
